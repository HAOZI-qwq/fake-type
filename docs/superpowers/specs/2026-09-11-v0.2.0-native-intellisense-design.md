# Fake Type v0.2.0 Native IntelliSense Design

## Goal

Make Fake Type preserve its existing "press arbitrary keys, output preset code" behavior while routing preset characters through VS Code's native typing pipeline so language completion providers receive real typing events. Add a configurable completion panel in the existing sidebar and publish a packaged v0.2.0 VSIX through GitHub Actions/Release.

## Root cause

The current implementation intercepts the `type` command and inserts preset characters with `TextEditor.edit()`. VS Code's suggestion model relies on editor typing/cursor events (including `onDidType` and keyboard-source cursor changes) for quick suggestions and trigger characters. A document edit is not equivalent to editor typing, so the previous wrapper-level `triggerSuggest` fallback could not reproduce the normal path reliably.

VS Code registers an overridable `type` command together with a `default:type` command that reaches the original editor handler. Therefore Fake Type can keep intercepting the physical key while sending the preset character through `default:type`.

## Architecture

1. Replace mapped-character `editor.edit()` insertion with `vscode.commands.executeCommand('default:type', { text: nextChar })`. This is the primary fix and is responsible for native typing events.
2. Keep the existing `type` override, queue, file mapping, terminal subsystem, deletion behavior, and progress tracking.
3. Add a completion settings model persisted in extension global state:
   - `enabled`: default true.
   - `mode`: `native`, `nativeFallback`, or `always` (default `nativeFallback`).
   - `delayMs`: default 80, allowed 0-500.
   - `triggerPolicy`: `identifier`, `code`, or `always` (default `code`).
   - `syncAcceptedCompletion`: default true.
   - `diagnostics`: default false.
4. In `native` mode, no forced command is sent; VS Code handles suggestions from the native typing event.
5. In `nativeFallback`, schedule `editor.action.triggerSuggest` after the configured delay only when the trigger policy allows it. Native suggestions are still free to appear first.
6. In `always`, schedule the same command after every eligible mapped character.
7. Register `workspace.onDidChangeTextDocument` to advance the preset index when a completion inserts additional text that still matches the preset prefix. Never move the index backward in this listener; Ctrl+Z handling remains with the existing force-sync before the next fake key.
8. Add a “代码补全” card to `fakeTypePasteArea` with an enable switch, mode selector, delay field, trigger policy selector, accepted-completion sync switch, diagnostics switch, reset-defaults action, and a “测试补全” button.
9. Remove the separate `extensionWrapper.ts`/old suggestion scheduler entrypoint after the new behavior is integrated into `extension.ts`; return the extension entrypoint to `./out/extension.js`.
10. Version package metadata to 0.2.0 and update repository URL to the fork.

## Testing

- Unit-test settings normalization and trigger-policy decisions.
- Unit-test preset prefix synchronization as a pure helper.
- Keep existing scheduler tests only if the scheduler remains; otherwise replace them with the new helper tests.
- GitHub Actions must pass `npm ci`, `npm test`, `npm run compile`, VSIX packaging, and artifact upload.

## Release

On successful v0.2.0 build, create tag `v0.2.0`, GitHub Release `Fake Type v0.2.0`, and attach `fake-type-0.2.0.vsix`. Release notes must mention native IntelliSense integration, sidebar completion controls, completion index synchronization, and the prior v0.1.0 compatibility baseline.
